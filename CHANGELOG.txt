ROCCAT Manager Full — Changelog
================================

@6 — 2026-09-19 (stuck-modifier fix, busy lock, active-profile memory)
  - Stuck keyboard modifier fix: a mouse button bound to Ctrl/Alt/Shift/Win could leave
    that modifier "held" in Windows after a profile switch (keyboard goes dead). New
    kone_xp_air/winput.py release_modifiers() sends synthetic key-ups (ctypes SendInput,
    no-op off Windows); run_mouse_job fires it after every mouse op, and a "Release stuck
    keys" footer button + POST /api/release-modifiers give a one-click manual recovery
    (the endpoint deliberately does NOT take MOUSE_LOCK so it works mid-push).
  - Packaging fix: kone_xp_air.winput added to roccat_manager.spec hiddenimports — server.py
    imports it at load, so without it the windowed exe closed on launch (ModuleNotFoundError).
  - Busy lock: while a push/switch rewrites onboard memory (~15 s) the UI shows a "Writing
    to the mouse..." overlay and refuses any new mouse operation, so two writes can't overlap
    (an overlapping write can corrupt a profile or strand a modifier). Wraps push-slot,
    push-to-mouse, push-all, and switch.
  - Active-profile memory: the onboard slot the mouse was last set to is persisted
    (slots.json "active_slot", written in run_mouse_job) and returned by GET /api/slots/{boot};
    a fresh launch now highlights the profile the mouse is on instead of nothing.
  - Keybind list gained the bare modifiers Ctrl/Shift/Alt (+ right variants) and Escape for AutoCAD
    (Esc cancels the current command).
  - Windows key on a button is NOT possible on the Kone XP Air: both a standalone scancode
    (00 e3 00 06) and the modifier-byte form (00 00 08 06) were tried on hardware and did nothing;
    Swarm II never binds a lone Win either (only Win+<key>, e.g. WWM.dat 00 0b 08 06). Removed the
    bare "Win" option from the button menu; the experimental encoding was reverted. For a Start-menu
    button use Ctrl+Esc; Win+<key> shortcuts (Show Desktop, Snipping Tool) already work.
  - Tests: 97 pass (active-slot persistence, read-does-not-clobber, Escape binds as a plain key).
  - DPI-set-in-app "does nothing": ROOT-CAUSED against a live Frida capture of Swarm II writing DPI
    (tools/capture_swarm_dpi.py). The 0x46 profile block roccat_write generated had bytes 31-32 = 06 ff;
    Swarm's wire write has 01 00 there, and the mouse rejects the block otherwise. Fixed: bytes 31-32 ->
    01 00, byte 5 = 0x1f, page-select flag 0x01, commit 06 01 46 06 03 ff <cs16 over the 76 bytes =
    block + 0xff>. ProfileBlock/write_profile_block now reproduce the captured wire write byte-for-byte,
    pinned in test_sequences (test_profile_write_matches_the_swarm_dpi_capture) and test_protocol.
    (Detour: the .dat FILE stores this block differently — byte 5 = 0x02, a real colour-B — so it is NOT
    the wire form; matching the .dat first was a wrong turn, corrected once the wire was captured.)
    tools/capture_swarm_dpi.py + .js: Frida logger that records Swarm's HID writes (filters the 0x4d
    lighting stream). PENDING final hardware re-verify (pointer speed should change on push).
  - Added toward RGB-off (same block): "Toggle RGB" button option (wire 00 00 0b 08, in the confirmed
    0x47 block) turns onboard lighting off with a button press today; "Read back" diagnostic next to the
    DPI field. Persistent lighting-off (default) is next, once DPI is confirmed on hardware.
